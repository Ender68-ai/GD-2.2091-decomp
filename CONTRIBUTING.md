# Contributing

Contributions to reverse-engineering research and reconstruction
are welcome.

## Guidelines

1. Preserve evidence from the original binary.
2. Do not invent function signatures or class members.
3. Clearly distinguish confirmed information from hypotheses.
4. Include addresses when documenting recovered functions.
5. Keep reconstructed code organized by subsystem.
6. Document unresolved types and unknown behavior.
7. Do not commit proprietary binaries or game assets.

## Naming

Use recovered names when reliable.

When names are unknown, use descriptive temporary names and
include the corresponding address.

## Verification

A reconstruction should only be marked verified when its
behavior or structure has supporting evidence.
